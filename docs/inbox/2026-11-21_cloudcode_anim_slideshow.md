# Облако → управляющему: «слайдшоу» эффектов заклинаний на сервере (руны, магические круги)

Ветка `claude/cnpc-chats-repo-0hcody`. Сборка `./gradlew build --offline -q` — зелёная, тесты 172/172 (новых 11).
Тестовый jar **не собирал** (по заданию). `builds/pohsmp_core-1.16.0.jar` не тронут.

Уточнение владельца: дёргаются **эффекты** (руны, круги, сигилы), не позы игрока. Позы игрока (PlayerAnimator/Iron's,
TargetPoseClient, BossPoseClient, NpcCastClient) я тоже проверил: они тикаются клиентом и рисуются с partialTick, пакеты их не
перезапускают каждый тик (TargetPose/BossFinisher шлют старт/стоп один раз) — там причины не нашёл, не трогал.

## Найденные причины

### 1. Главная: время эффектов считалось во `float` — у старого мира дробная часть тика пропадает
Везде в клиентском визуале было `level.getGameTime() + partialTick`. Это `long + float`, Java считает во **float**
(24 бита мантиссы). gameTime — возраст мира в тиках, он не сбрасывается. Чем старше мир, тем грубее:

| gameTime (тиков) | реального времени работы мира | что остаётся от partialTick 0 / .25 / .5 / .75 |
|---|---|---|
| 720 000 | 10 ч | 0 / .25 / .5 / .75 — плавно |
| 4 200 000 | ~58 ч | 0 / 0 / .5 / 1 — полшага |
| 8 400 000 | ~117 ч | 0 / 0 / 0 / 1 — раз в тик |
| ≥ 16 777 216 | ≥ ~9,7 суток | 0 / 0 / 0 / 0 — **20 кадров/с, «слайдшоу»** |

Сервер работает давно → у его мира gameTime большой → руны, круги, сигилы, камеры катсцен двигаются раз в тик при любом FPS.
Одиночный тестовый мир молодой → там плавно. Это объясняет «на сервере слайдшоу, в одиночке нормально».
Проверить: `/time query gametime` на сервере.

### 2. Клиентское gameTime не монотонно на выделенном сервере
Клиент сам прибавляет 1 к gameTime каждый тик, а сервер раз в 20 своих тиков перезаписывает его пакетом `ClientboundSetTimePacket`.
При TPS < 20 клиент убегает вперёд и раз в секунду откатывается назад (при 14 TPS — примерно на 8 тиков); сетевой разброс даёт ±1–2
тика и при 20 TPS. Всё, что считалось от gameTime, дёргается назад-вперёд (тест `AnimClockTest` это воспроизводит).

Файлы (строки — до правки, совпадают с текущими):
- `client/fx/FxClient.java:60, 213` — все fx/сигилы/меши (руны, круги);
- `client/HigherFx.java:87, 170, 391, 429, 735` — круги/печати высших заклинаний;
- `client/DisintegrationFx.java:71, 111`;
- `client/GateStaff.java:92`, `client/fx/gate/GateManaRender.java:65` — посох и мана «Безмолвных врат»;
- `client/DownfallCut.java:83, 268, 298, 349, 350, 1062` — камеры катсцен;
- `boss/client/BossCam.java:155, 178, 207, 209, 211, 302, 304` — камеры боссов;
- `client/EmberWhipClient.java:157, 166, 212, 242, 247, 260, 269, 339` — хлыст;
- таймеры: `client/HiddenHands.java:31, 57`, `client/OutfitAnim.java:79, 86`, `client/JointFx.java:41, 56`,
  `client/illusion/Ghosts.java:28, 38`, `boss/client/BossHudClient.java:44`, `boss/client/BossBarClient.java:58`.

Все моменты в этих местах **относительные** (время получения пакета + возраст/длительность из пакета), абсолютное серверное
время клиент нигде не сравнивает — поэтому замену можно делать «один к одному».

### 3. Движущиеся эффекты прыгали от пакета к пакету
`FxMsg.MOVE` (`client/fx/FxClient.java:87-101`) ставил эффект сразу в новую точку. Сервер шлёт MOVE каждый свой тик:
печати «Восьми щитов» (`spell/EightShieldsSpell.java:114`, вращаются вокруг кастера), копья ветра, клинки забвения, залп,
огненный хлыст, стены и стрелы Эреба (`boss/erebhand/ErebHandFight.java:515, 811`), модули «Дома». Движение было не плавнее
пакетов: максимум 20 шагов/с, на сервере меньше и неровно (пакеты приходят пачками).

## Что исправлено
1. **`fx/AnimClock.java`** (новый, чистая логика) — монотонные часы: свой счётчик клиентских тиков, `now(pt)` в **double**.
2. **`client/ClientClock.java`** (новый) — клиентский экземпляр часов, тикает в `ClientTickEvent` END (HIGHEST), стоит на паузе
   одиночной игры, как и время мира. Серверные пакеты его не трогают. Зарегистрирован в `ClientInit`.
3. Во всех файлах из п.2: `….getGameTime() + pt` → `ClientClock.now(pt)`, `….getGameTime()` → `ClientClock.ticks()`.
4. **`fx/MoveSmooth.java`** (новый, чистая логика) + `FxClient`: MOVE теперь запускает скольжение от текущей нарисованной точки
   к новой за измеренный интервал между MOVE (1..6 тиков); yaw — коротким путём; скачок > 8 блоков — телепорт без скольжения.
   Цена: эффект отстаёт от сервера на ~1 интервал MOVE (при 20 TPS — 1 тик, 50 мс).
5. Тесты: `src/test/java/ru/pohsmp/core/fx/AnimClockTest.java` (лагающий сервер 8–25 TPS, пакеты времени с запаздыванием: старое
   время прыгает назад, часы — монотонны и без скачков; «30 часов игры» — точность держится), `MoveSmoothTest.java` (печать «Восьми
   щитов» при 14 TPS с пачками пакетов: худший шаг за кадр заметно меньше, чем при прыжках; телепорт; yaw через 180°; демонстрация
   потери partialTick во float при gameTime 16,8 млн).
   Тест сразу поймал ту же ошибку в моём `now()` (`long + float`) — исправлено приведением к double.

Не трогал (мелочи, не «слайдшоу»): `client/fx/SigilDraw.java:61-62` — дочерние сигилы на кастере берут `getYRot()`/`position()`
без partialTick, но только один раз при появлении; `client/nightmare/NightmareWorld.java:45` — `gameTime % 100`, не анимация.

   `MinecraftForge.EVENT_BUS.register(ClientClock.class);`
3. Во **всех клиентских** файлах (на ПК — найти поиском `getGameTime()` в `client/` и `*/client/`, список из п.2 причин), правило:
   - `X.getGameTime() + pt` / `+ e.getPartialTick()` / `+ mc.getFrameTime()` / `+ Minecraft.getInstance().getFrameTime()`
     → `ClientClock.now(тот же аргумент)` (вне пакета `ru.pohsmp.core.client` — с полным именем `ru.pohsmp.core.client.ClientClock`);

4. `client/fx/FxClient.java`:

     первом MOVE и вызвать `i.glide.move(ClientClock.now(mc.getFrameTime()), m.x, m.y, m.z, m.yaw, m.pitch)`;
   - в `onRender` в цикле сразу после `Inst i = it.next();` — `i.glide(time);`.
   Точный вид — `git show` этого коммита, файл `FxClient.java`.

## Что проверить на сервере
1. `/time query gametime` — если больше ~4 млн, старый jar точно «рубит» дробную часть тика.
2. **Без лагов, старый мир**: кастануть заклинание с рунами/кругами (Восемь щитов, Распад, печати высших, Врата), смотреть на
   вращение кругов при 60+ FPS. Старый jar — ступеньками, новый — плавно. Тот же эффект воспроизводится и в одиночке, если
   скопировать туда мир сервера (большой gameTime) — удобно сравнить без сервера.
3. **Лаг сервера** (в 1.20.1 нет `/tick`): нагрузить мир — например, закрытая коробка с 1500–2000 мобами (`/summon` в
   повторяющемся командном блоке, потом выключить) или тяжёлый датапак с функцией на каждый тик; смотреть `/forge tps`
   (нужно 10–15). На старом jar круги раз в секунду дёргаются назад; на новом — плавно (эффект живёт по часам клиента,
   длительность — как пришла, конец — по STOP с сервера).
4. Движущиеся эффекты: печати «Восьми щитов» вокруг кастера, копья ветра, клинки забвения, стены Эреба — должны скользить,
   без ступенек; телепорт эффекта (> 8 блоков) — мгновенно.
5. Регресс: катсцены (камеры Падения, Врат, боссов) — тайминги те же; скрытые руки на касте, кот Неро, хлыст — работают как раньше.
6. Свой игрок и чужие: эффекты считаются одинаково для всех (часы общие на клиента), разницы быть не должно.
